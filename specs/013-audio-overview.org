* Goal

NotebookLM's Audio Overview turns a source into a spoken podcast
script.  org-learn's version: from the current subtree, generate a
SPOKEN-WORD SCRIPT in one of three formats — =brief=, =deep-dive=, or
=debate= (two hosts) — through the existing single network choke point
=org-learn-ai--complete=.  The script lands in its own Org buffer,
ready to read, edit, copy or save.  Text-to-speech playback and audio
synthesis are deliberately OUT of scope for this segment (the DoE
notice cuts them too); the script is plain spoken text, which is the
seam a future TTS segment (the org-ai/whisper research lane in
agent-team/IDEAS.org) can read.

* System prompts (three defconsts, pinned verbatim contract)

The prompt text IS the output-format contract; the parse law below
enforces it.  Pin these three defconsts:

- =org-learn-ai--audio-brief-prompt=: "You write the script for a SHORT
  audio overview of the study context, about one minute spoken, for a
  listener who has never read it.  Cover the core idea, the key facts
  and one takeaway.  Spoken sentences only: plain text, no markdown,
  no headings, no speaker labels."
- =org-learn-ai--audio-deep-dive-prompt=: "You write the script for a
  DEEP-DIVE audio overview of the study context, about five minutes
  spoken.  Structure it as a spoken introduction, a walk-through of the
  key ideas in order with a short example each, and a spoken summary
  that names open questions.  Spoken sentences only: plain text, no
  markdown, no headings, no speaker labels."
- =org-learn-ai--audio-debate-prompt=: "You write the script for a
  TWO-HOST audio overview debate about the study context.  HOST A
  advocates the study context's main claim; HOST B challenges it; the
  final turns converge on the strongest synthesis both hosts accept.
  Every turn is one line starting with the speaker label 'HOST A:' or
  'HOST B:', strictly alternating, HOST A first.  Spoken sentences
  after the label only: no markdown, no headings."

* Messages law

=org-learn-ai--audio-messages (format context)= returns exactly two
messages: the format's system prompt, then ONE user message with the
uniform shape (the flashcards law, =org-learn-ai--flashcards-messages=
:575): ="Study context:\n%s\n\nWrite the audio overview script now."=
with the ="(no subtree at point)"= fallback for an empty context.  The
format identity travels ONLY in the system prompt; the user turn is
format-independent (pinned: tests assert the user sentence is byte-
identical across all three formats).

* Parse law (validation; garbage -> user-error, no litter)

=org-learn-ai--audio-parse (format reply)=:

- =brief= / =deep-dive=: =string-trim= the reply; blank result is
  garbage — =user-error= naming the format (the flashcards garbage law,
  =org-learn-ai--cards-from-array= :526).  Otherwise the trimmed
  string IS the script body; no markdown sanitization (the prompt law
  asks for plain text; honesty beats rewriting the model).
- =debate=: split the reply into lines and drop blank lines.  A line
  starting with the literal =HOST A: = or =HOST B: = (case-sensitive,
  anchored at line start) opens a NEW turn; any other non-blank line is
  a CONTINUATION of the previous turn (appended with one space) —
  models wrap long turns at ~80 columns and the script must survive
  that.  A continuation line before any labeled line is garbage.
  Turn laws: at least 2 turns; turn 1 is HOST A; strict alternation
  (no two adjacent turns share a speaker).  Any violation is garbage:
  =user-error= "no usable audio script in the model reply" style.
  Result: a list of =(LABEL . TEXT)= conses, LABEL the string =HOST A=
  or =HOST B=, TEXT the trimmed joined turn.

* Render law (pure)

=org-learn-ai--audio-render (format heading source-line script)=
returns the complete buffer text, exactly this shape:

#+begin_src org
#+TITLE: Audio overview (brief) — Memory
Source: [[file:/path/to/notes.org::12][Memory]]

<script body — debate: one "HOST A: ..."/"HOST B: ..." line per turn,
in parsed order, labels rebuilt from the conses>

-----
Generated by org-learn-ai audio overview (spec 013) from the source
subtree; text-to-speech playback is out of scope for this segment.
#+end_src

- Title line: =(format "#+TITLE: Audio overview (%s) — %s" format heading)=.
- =source-line= is passed in whole (the command side builds it; next
  section) so the renderer stays pure and testable.
- Debate body: one turn per line, =(format "%s: %s" label text)=,
  joined with newlines.  Brief/deep-dive body: the trimmed reply as-is.
- Footer: the two pinned lines above (honesty: the script states its
  origin and the TTS scope cut).

* Source line law

=org-learn-ai--audio-source-line (heading)=, run in the INVOKING
buffer before any switch: when =(buffer-file-name)= is set, return
=Source: = plus the org link built with the dashboard growth-areas link
law (spec 012): =(org-link-make-string (format "file:%s::%d" file line) heading)=
where =file= is the buffer's file and =line= is
=(line-number-at-pos)= at the heading start (after
=org-back-to-heading=).  When the buffer is unsaved, return the plain
fallback =(format "Source: %s (unsaved buffer)" heading)= — honest
degradation, never a bogus =file:nil= link.

* Buffer law

- Buffer name const =org-learn-ai--audio-buffer= = ="*org-learn-ai-audio*"=.
  ONE buffer for all formats; every generation RESETS it
  (=erase-buffer=, the chat welcome-reset pattern) — the title line
  carries the format, so history is not needed.
- Major mode: =org-mode= (the script is Org text; the user can C-x C-s
  it to a file or copy turns elsewhere).  NOT read-only: a script is a
  draft to tweak before speaking (the dashboard read-only law does not
  apply here).
- The interactive command =pop-to-buffer=s after rendering.  The CORE
  does NO window operations — batch-safe, so ERT drives it directly
  (the =org-learn-ai--mode-chat= pop-inside pattern is deliberately
  NOT followed; pinned for testability).

* Core and command law

=org-learn-ai--audio-overview (format)= — format a symbol from the
closed vocabulary; the only stateful piece:

1. =(org-learn-ai--subtree-check "org-learn-ai-audio-overview")= —
   guard FIRST; no subtree, no network.
2. =context = (org-learn-ai--context)=; one choke call:
   =reply = (org-learn-ai--complete (org-learn-ai--audio-messages format context))=.
3. =script = (org-learn-ai--audio-parse format reply)= — garbage raises
   =user-error= BEFORE any buffer is created or touched (no-litter law,
   the flashcards precedent).
4. Capture the source facts in the invoking buffer: heading text, and
   =source-line = (org-learn-ai--audio-source-line heading)=.
5. =text = (org-learn-ai--audio-render format heading source-line script)=;
   reset =*org-learn-ai-audio*=, insert, =org-mode=.
6. Return the audio buffer.

The command =org-learn-ai-audio-overview= (autoload, interactive)
wraps the core: =completing-read= over the three format NAMES
(=org-learn-ai--audio-formats=, a pinned defconst list) with
=org-learn-ai-audio-default-format= as the preselected default, =intern=
the answer, call the core, =pop-to-buffer=, point at end, and
=message= one line: ="org-learn-ai: audio overview (%s) ready"= with
the format name.
