* Goal

NotebookLM's study kit turns a source into three study artifacts at once:
a STUDY GUIDE (how the material fits together, a study path, self-check
questions), a GLOSSARY (the terms, defined), and a BRIEFING DOCUMENT (a
concise shareable summary for a reader who must act).  org-learn's
version: from the current subtree, generate all three as Org buffers,
through the existing single network choke point =org-learn-ai--complete=.
Two controls shape every artifact: a TOPIC focus (a string, default the
subtree heading) and a DIFFICULTY (closed vocabulary: =introductory=,
=intermediate=, =advanced=).  Separately, the quiz loop's misses get an
EXPLAIN: one more choke call whose answer cites the source heading back
through an org-id link, so a wrong answer routes the learner to the exact
entry that teaches it.  Text-to-speech, mind maps and guided-learning
plans are other DoE items (5, and item 4) — deliberately OUT of scope
here.

* System prompts (four defconsts, pinned verbatim contract)

The prompt text IS the output-format contract; the parse law below
enforces it.  Pin these four defconsts:

- =org-learn-ai--study-guide-prompt=: "You write the STUDY GUIDE section
  of a study kit about the study context.  Cover the core idea, the key
  concepts and how they connect, then a short study path of 3-5 steps and
  three self-check questions.  Plain Org text: short sections separated
  by blank lines, no markdown fences, no title line."
- =org-learn-ai--glossary-prompt=: "You build the GLOSSARY section of a
  study kit.  Reply with only a JSON array of 5-10 objects with keys
  \"term\" and \"definition\"; no prose, no markdown fences."
- =org-learn-ai--briefing-prompt=: "You write the BRIEFING DOCUMENT of a
  study kit about the study context: a concise, shareable summary for a
  reader who must act on it.  Cover what the subject is, why it matters
  and the three things to remember.  Plain Org text: short paragraphs, no
  markdown fences, no title line."
- =org-learn-ai--explain-prompt=: "You are a study tutor explaining a
  missed quiz answer.  Explain why the correct answer is correct and the
  learner's answer fails, in at most three short paragraphs, citing
  facts from the study context.  Plain text, no markdown fences."

- =org-learn-ai--explain-messages (context question answer)= returns

* Parse laws (validation; garbage -> user-error, no litter)

- =org-learn-ai--kit-parse (artifact reply)= dispatches:
  - =guide= / =briefing=: =string-trim= the reply; blank result is
    garbage — =user-error= naming the artifact (the flashcards garbage
    law, :526).  Otherwise the trimmed string IS the body; no markdown
    sanitization (the prompt law asks for plain Org text; honesty beats
    rewriting the model — spec 013's law).
  - =glossary=: =org-learn-ai--glossary-from-reply (reply)=.
- =org-learn-ai--glossary-from-reply (reply)=: the =org-learn-ai--extract-
  json-array= (:500) scan shape — each ="["= position tried as the array
  start until one parses — with a NEW validator: a non-empty vector of
  alists where every item has a string =term= and a string =definition=,
  both non-blank after trim.  Usable items become =(TERM . DEFINITION)=
  conses in order; unusable items are DROPPED (the =--cards-from-array=
  drop law); when nothing usable remains, =user-error= "No usable
  {term, definition} entries in the model reply".  The flashcards
  validator and =--extract-json-array= stay byte-identical (additive
  law); the duplication is conscious — the key sets differ — and a
  future refactor segment may share the scanner.
- =org-learn-ai--explain-parse (reply)=: =string-trim=; blank is garbage
  — =user-error= "no usable explanation in the model reply" style.

* Render laws (pure)

=org-learn-ai--kit-render (artifact heading source-line topic difficulty
body)= returns the complete buffer text.  Artifact display names (pinned
const table): =guide= -> "study guide", =glossary= -> "glossary",
=briefing= -> "briefing doc".  Exact shape:

#+begin_src org
#+TITLE: Study kit (study guide) — Memory
Source: [[file:/path/to/notes.org::12][Memory]]
Topic: Memory
Difficulty: intermediate

<body — glossary: one "TERM :: DEFINITION" Org definition-list line per
entry, in parsed order; guide/briefing: the trimmed reply as-is>

-----
Generated by org-learn-ai study kit (spec 014) from the source subtree.
#+end_src

- Title line: =(format "#+TITLE: Study kit (%s) — %s" display heading)=.
- =source-line= is passed in whole (the command side builds it; next
  section) so the renderer stays pure and testable (spec 013 law).
- Glossary body: =(format "%s :: %s" term definition)= per cons, joined
  with newlines — Org definition-list syntax, native and readable.
- Footer: the two pinned lines above (honesty: the buffer states its
  origin).

=org-learn-ai--explain-render (heading cite question answer body)=
returns:

#+begin_src org
#+TITLE: Study-kit explain — Memory
Source: [[id:2c0bb0c0-15c7-4964-b85a-53ac39e544de][Memory]]
Missed question: What is the SM-2 ease law?
My answer: It lowers ease on lapses.

<body — trimmed explain reply>

-----
Generated by org-learn-ai study kit (spec 014): quiz-miss explain with
an org-id citation back to the source heading.
#+end_src

- =cite= is passed in whole (built by the source-cite law below).
- =question= / =answer= are inserted verbatim on their pinned lines.

* Core and command laws

=org-learn-ai--kit (topic difficulty)= — topic a string, difficulty a
symbol from the closed vocabulary; the only stateful piece:

1. =(org-learn-ai--subtree-check "org-learn-ai-study-kit")= — guard
   FIRST; no subtree, no network.
2. =context = (org-learn-ai--context)=; capture heading text and
   =source-line = (org-learn-ai--kit-source-line heading)= in the
   invoking buffer.
3. THREE choke calls in PINNED order — guide, glossary, briefing:
   =reply = (org-learn-ai--complete (org-learn-ai--kit-messages
   artifact context topic difficulty))= for each artifact.
4. Parse ALL THREE (=org-learn-ai--kit-parse=) BEFORE any buffer is
   created or touched — any garbage raises =user-error= with ZERO kit
   buffers in existence (the parse-all-then-render no-litter law;
   stronger than spec 013's single-artifact law, pinned because the kit
   is three artifacts).
5. Render each artifact (=org-learn-ai--kit-render=), reset its buffer,
   insert, =org-mode=.
6. Return the guide buffer.

The command =org-learn-ai-study-kit= (autoload, interactive) wraps the
core: =read-string= for the topic (prompt ="Topic focus (default: %s): "=
with the heading text as default; empty answer takes the default),
=completing-read= over the difficulty NAMES (=mapcar 'symbol-name
org-learn-ai--study-kit-difficulties=) with
=org-learn-ai-study-kit-difficulty='s name as the preselected default,
=intern= the answer, =memq=-guard it (unknown symbol = user-error — the
closed-vocabulary law), call the core, =pop-to-buffer= the guide buffer,
point at end, and =message= one line: ="org-learn-ai: study kit ready
(study guide, glossary, briefing doc)"=.

=org-learn-ai--explain-miss (question answer)= — both strings; the only
stateful piece:

1. =(org-learn-ai--subtree-check "org-learn-ai-explain-miss")= — guard
   FIRST.
2. =context = (org-learn-ai--context)=; capture heading; ONE choke call:
   =reply = (org-learn-ai--complete (org-learn-ai--explain-messages
   context question answer))=.
3. =body = (org-learn-ai--explain-parse reply)= — garbage raises
   =user-error= BEFORE any buffer is touched (no-litter law).
4. =cite = (org-learn-ai--explain-source-cite heading)= — the org-id
   side effect (property insertion) happens HERE, in the invoking
   buffer, after the network succeeded.
5. =text = (org-learn-ai--explain-render heading cite question answer
   body)=; reset =*org-learn-ai-explain*=, insert, =org-mode=.
6. Return the explain buffer.

The command =org-learn-ai-explain-miss= (autoload, interactive) wraps
the core: =source-buffer = (current-buffer)= captured FIRST (the quiz
loop's pattern, :649); =read-string= the missed question (empty ->
=user-error= "no question to explain") and the learner's answer; call
the core; =pop-to-buffer= the explain buffer, point at end; then the
save-offer law — when =source-buffer= is file-visiting,
=yes-or-no-p "Save the source buffer so the new :ID: property
persists? "= and on yes =(with-current-buffer source-buffer
(save-buffer))=; =message= one line: ="org-learn-ai: explain ready"=.
